2. The Core Principle

The defining architectural design of Manifest Journal is absolute local privacy. No personal data, written entries, goal definitions, multimedia files, identity credentials, or telemetry metrics are collected, transmitted, stored on any remote server, or shared with any third-party entity. Ever. This commitment is not merely an aspirational policy promise or contractual declaration; it is a structural mathematical guarantee enforced by the software architecture itself. There is no remote backend server, no cloud database, no user authentication platform, and no remote API endpoint configured anywhere in this software to receive or process your data.

All interactions occur exclusively inside your local device runtime environment.

4. How Your Data Is Stored

All information you author or capture inside Manifest Journal is stored entirely on your physical device using standard client-side browser storage sandboxes:

Structured user data—including your local profile records, multi-horizon goals, daily journal entries, scripting pages, teleprompter written scripts, album metadata, streak counters, and application appearance preferences—is persisted locally using the browser's native IndexedDB database engine (under the database name manifest-journal-db). High-capacity binary media assets—specifically your captured photos, video affirmations, and recorded spoken teleprompter sessions—are written directly to the Origin Private File System (OPFS), an encrypted, highly performant browser-isolated sandboxed virtual file system accessible only through secure origin APIs.

Both IndexedDB and the Origin Private File System are strictly sandboxed to the exact web origin of Manifest Journal by the browser's same-origin security model. They are completely inaccessible to other websites, inaccessible to external third-party software, inaccessible to the developer, and are permanently erased whenever you choose to clear your browser's site storage.

5. Camera and Microphone Usage

Manifest Journal requests access to your device's camera and microphone strictly for real-time, user-directed capture features: taking your initial onboarding selfie, capturing intentional photos or video affirmations in the Album, and recording spoken affirmation rehearsals within the Teleprompter module.

Media streams are processed entirely in local volatile memory. The raw video and audio streams never leave your device and are never broadcast or streamed across any computer network. When a capture is finalized, the resulting binary file is saved solely into your private OPFS sandbox on your hardware. Media assets captured within Manifest Journal are NOT automatically copied or exposed to your device operating system's general photo library or camera roll, ensuring complete confidentiality from other device applications unless you explicitly tap the "Download" button to manually save a specific file. Whenever a camera or microphone interface is closed, all hardware media tracks are immediately and permanently terminated.

6. Notifications and Reminders

Manifest Journal provides optional daily ritual reminders (such as morning goal setting and evening journaling reflection). These notifications are generated entirely on-device by the registered Progressive Web App Service Worker (sw.js). The application does not utilize any external Web Push server, does not maintain a cloud notification delivery pipeline, and does not register a push subscription token with any remote service.

Permission to display notifications is requested only after you intentionally complete your personal Commitment ceremony. You retain full control over this capability at all times; revoking notification permissions in your browser or operating system settings instantly and permanently silences all scheduled local alerts without impacting any other app functionality.

7. Third-Party Services

Manifest Journal avoids third-party dependencies. The only external network resource queried by the application is Google Fonts (hosted across fonts.googleapis.com and fonts.gstatic.com) to deliver the typographic Roboto typeface stylesheet. When you first load the application online, your browser issues a standard HTTP request to Google's content delivery servers, transmitting your temporary IP address as part of normal web routing. Once downloaded, the application Service Worker caches the font files locally within browser cache storage, and Google's servers are never contacted again during subsequent offline or online launches. For information on how Google handles font network requests, you may consult Google's Privacy Policy.

The Knowledge screen contains informative educational text on manifestation principles. Manifest Journal loads zero third-party tracking scripts, zero social media pixels, zero software development kits (SDKs), and zero third-party advertising frameworks.

8. Data Export and Portability

You maintain unconditional ownership and sovereignty over your data. Manifest Journal provides a built-in export mechanism accessible via Settings → Complete Data Backup. When invoked, a lightweight, client-side JavaScript archiving engine (JSZip) bundles all your IndexedDB database records (serialized as human-readable JSON files) and all your stored OPFS binary photos and video recordings into a single offline archive named in the format manifest-journal-export-YYYY-MM-DD.zip.

This archive is generated strictly in local volatile memory and triggered as a direct browser file download to your device storage. The data is never uploaded, inspected, or buffered on any server. Because the resulting ZIP archive is unencrypted for maximum open portability, we strongly advise users to store their exported archives on password-protected or hardware-encrypted storage media, treating the file with the same confidentiality as a personal paper diary.

9. Data Deletion and Erasure

You have absolute authority to delete all your information at any moment through three independent methods:

  • In-App Immediate Reset: Navigating to Settings → Clear All Data & Reset App immediately executes an automated wipe of all IndexedDB database object stores, purges all stored media from the Origin Private File System, unregisters active service worker caches, and resets application state to a clean slate.
  • Browser Storage Management: Clearing cookies and site data for the application's domain within your browser settings instantly deletes the sandboxed IndexedDB storage and OPFS directory.
  • PWA Uninstallation: Removing the Progressive Web App from your mobile home screen or desktop application manager and confirming the deletion of associated offline site data accomplishes complete erasure.

Please note that because the developer maintains no servers, accounts, or cloud backups, once data deletion is performed, your information is permanently and irretrievably erased. We cannot recover deleted journals, goals, or media under any circumstances.

10. Children's Privacy

Because the application does not collect, harvest, store, or transmit personal information from any user regardless of age, compliance with global child privacy regulations—including the United States Children's Online Privacy Protection Act (COPPA), the European Union General Data Protection Regulation (GDPR), and India's Digital Personal Data Protection Act (DPDPA)—is satisfied inherently by our zero-collection technical design.

Security Policy

Effective Date: TBD — fill before publishing  |  Last Updated: TBD — fill before publishing

1. Supported Versions

Security audits, vulnerability triage, and maintenance patches are actively provided solely for the latest published release and current main branch of the Manifest Journal codebase hosted in the official GitHub repository. Because Progressive Web Apps update automatically via Service Worker asset lifecycle management, users are encouraged to stay connected briefly to allow automatic cache updating to the latest secure version.

2. Security Architecture — Why This App Is Structurally Secure

Manifest Journal eliminates the vast majority of traditional web vulnerability classes through intentional architectural choices:

  • Zero Server Surface: Because there is no backend web server, database cluster, microservice API, or cloud storage container, traditional remote server breaches, SQL injection attacks, remote code execution (RCE) on servers, and database leaks are structurally impossible.
  • No Authentication Credentials: The application does not require usernames, passwords, session tokens, or JWTs. There are no authentication credentials stored on any machine to intercept, brute-force, or compromise.
  • Origin Sandboxing: All structured data stored in IndexedDB and binary media written to the Origin Private File System (OPFS) are strictly sandboxed by browser security kernels to the application's unique origin. Other websites, scripts from other tabs, and external applications cannot read or tamper with your records.
  • Safe DOM Rendering & Input Sanitization: User-authored text across journal moments, scripts, and goal titles is handled securely and sanitized prior to persistence. Raw strings are never evaluated using dangerous APIs such as eval() or insecure innerHTML assignments.
  • Transport Security (HTTPS Enforcement): Modern web browser engines mandate secure contexts (HTTPS) for all privileged web capabilities employed by this app, including Camera access, Microphone access, Service Workers, and OPFS filesystem access.

3. Content Security Policy (CSP)

To prevent unauthorized script execution and defend against Cross-Site Scripting (XSS) vectors, Manifest Journal operates under a strict Content Security Policy. The enforced policy directives are defined as follows:

default-src 'self'; script-src 'self'; style-src 'self' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; img-src 'self' blob: data:; media-src 'self' blob:; connect-src 'none';

Under this policy, executable JavaScript is restricted strictly to first-party application bundles. External stylesheet loading is restricted to self and Google Fonts, font binaries are restricted to Google's static CDN, and outbound asynchronous network connections (such as fetch or XMLHttpRequest) are blocked (connect-src 'none'), guaranteeing that client scripts cannot exfiltrate data to remote endpoints.

4. User Security Responsibilities

Because security in a local-first application is anchored directly in the user's physical client environment, you are advised to observe the following essential security practices:

  • Maintain a strong device passcode, PIN, or biometric screen lock to prevent physical inspection of your browser by unauthorized individuals.
  • Store exported .zip archive backups in secure, encrypted locations (such as encrypted drives or secure storage volumes).
  • Keep your web browser and operating system regularly updated to ensure you possess the latest security patches against sandbox escapes.
  • If using a shared family or public device, utilize private browsing windows or perform Settings → Clear All Data before concluding your session.

5. Known Security Limitations

For complete transparency, users should understand the inherent boundary limitations of client-side browser storage:

  • Physical Device Access: Anyone who has unlocked physical access to your device browser can launch Manifest Journal and view your local journals, goals, and media.
  • Unencrypted Export Archives: Backups downloaded via the export tool are unencrypted ZIP containers. They should be treated with the same confidentiality as a physical notebook.
  • Browser Eviction Under Storage Pressure: On devices experiencing extreme physical storage exhaustion, browser operating systems can theoretically evict origin storage data if not flagged as persistent. Users should maintain regular exported backup archives to prevent data loss.

6. Reporting a Vulnerability

We treat the security and privacy integrity of Manifest Journal with utmost seriousness. If you identify a security flaw, sandbox leakage, or policy bypass within the application, please DO NOT open a public GitHub issue or public discussion thread.

Instead, report the issue privately by sending an encrypted or direct email to developer Anshul Sethiya at anshuljain1189@gmail.com with the exact subject line:

Please include in your report:

  • A detailed description of the vulnerability and its potential security impact.
  • Step-by-step instructions or proof-of-concept steps demonstrating how to reproduce the issue.
  • The specific browser vendor, version, and operating system where the vulnerability was observed.
  • Any remediation proposals, patch diffs, or defensive recommendations you may have.

You will receive an initial response acknowledging your submission within 72 hours. If confirmed, a remediation patch will be prioritized immediately, and you will be credited in the repository release notes upon release (unless you request anonymity).
